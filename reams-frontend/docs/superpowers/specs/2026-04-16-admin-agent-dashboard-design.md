# Admin 与 AgentWorkspace 看板修复设计

日期：2026-04-16

## 1. 背景

当前 `Admin.vue` 与 `AgentWorkspace.vue` 都存在不同程度的源码污染与展示异常：

- 页面中出现中文乱码，且不只是字体问题，源码里本身就混入了错误编码后的文本。
- `AgentWorkspace.vue` 还包含损坏的模板标签、属性字符串和脚本内容，已经影响页面结构与可维护性。
- `Admin.vue` 的“近 6 个月成交趋势”在切换排行时间窗后会被错误刷新，并在部分情况下因为图表容器重挂载而空白。
- 两个页面虽然都属于看板页，但视觉细节、信息层级和操作入口组织不够统一。

## 2. 本次目标

本次工作只处理 `Admin` 和 `AgentWorkspace` 两页，目标如下：

1. 清理页面可见乱码，并恢复正常中文文案。
2. 修复 `Admin` 趋势图在切换排行时间窗后消失或不渲染的问题。
3. 让 `Admin` 保持现有布局，只做稳定性与样式细节修复。
4. 重组 `AgentWorkspace` 的业务模块和主结构，让它更像中介业务工作台。
5. 保持现有后端接口与统计口径，不额外扩散到其他业务模块。

## 3. 非目标

以下内容不在本次范围内：

- 不新增后端统计接口。
- 不改动数据库结构。
- 不重做全站视觉系统。
- 不把两个页面拆成大量新组件。
- 不调整其他页面的布局与文案。

## 4. 现状问题与根因

### 4.1 Admin

当前问题：

- 页面仍残留部分乱码文案。
- 趋势图在 `Top5` 时间切换时被连带刷新。
- 图表实例在容器被销毁后仍被复用，导致重新渲染失败。

根因判断：

- 之前文件经历过编码污染，模板、脚本和样式中的中文被错误写回。
- `salesWindow` 与趋势图数据请求耦合，导致排行切换触发趋势重载。
- ECharts 实例没有在宿主 DOM 变化后重新绑定。

### 4.2 AgentWorkspace

当前问题：

- 页面存在大面积乱码。
- 模板内有损坏的结束标签、属性值和脚本字符串。
- 业务模块顺序更像“信息堆叠”，不是“工作台”。

根因判断：

- 文件源码本身已损坏，不能依赖局部补丁持续修复。
- 当前模块虽然复用了现有数据，但没有按“结果优先、推进次之、操作最后”的顺序组织。

## 5. 设计方案

### 5.1 Admin 设计

`Admin` 采用保守修复方案，保留现有版式与区块，不做大规模重构。

保留的结构：

- 顶部 `Hero + 快捷入口 + 经营预警`
- 中间 `成交趋势 + 价格段分析 + 城市对比 + 区县分布`
- 右侧 `区县排行 + 头部中介 + 交易流程 + 经营提示`

改动重点：

1. 清理所有用户可见中文文案。
2. 清理 tooltip、图例、空态、按钮标题等隐藏展示文案。
3. 让排行时间窗和趋势时间窗解耦。
4. 趋势图在旧数据存在时不因其他请求进入空白态。
5. 当图表宿主节点变化时，主动销毁旧实例并重新初始化。

### 5.2 AgentWorkspace 设计

`AgentWorkspace` 允许调整主结构，但仍保持与 `Admin` 同一套看板氛围，不引入完全不同的视觉体系。

新的页面结构分为四层：

#### 第一层：顶部业务摘要

展示最关键的结果指标：

- 本月成交额
- 已完成带看
- 待跟进交易
- 服务评分或评价数

目的：

- 让中介进入页面后先看到结果而不是流程细节。

#### 第二层：核心图表区

左右双栏展示：

- 左侧：近 6 个月成交趋势
- 右侧：交易状态分布

目的：

- 先看业务节奏，再看各状态占比。

#### 第三层：业务推进区

展示业务过程信息：

- 带看推进情况
- 客户或交易转化信息
- 房源库存 / 区域分布

目的：

- 对“哪里卡住了、哪里还有空间”形成快速判断。

#### 第四层：快捷入口与重点提醒

保留并重排操作入口：

- 房源管理
- 带看管理
- 交易管理


同时放置轻量的提示信息，避免把提示混入核心图表区。

## 6. 数据与交互策略

### 6.1 Admin

- `loadDashboard()` 只负责概览、排行、分布等主看板数据。
- `loadTrendData()` 只负责趋势图月度数据。
- `salesWindow` 变化时，仅刷新排行相关内容。
- `trendWindow` 变化时，仅刷新趋势图数据。
- 趋势图渲染前检查 ECharts 实例绑定的 DOM 是否仍为当前容器，不一致则重建实例。

### 6.2 AgentWorkspace

- 保持使用现有工作台接口和字段。
- 先恢复稳定的数据结构和模板，再重排模块。
- 图表区统一采用和 `Admin` 相同的 ECharts 初始化与 resize 策略。

## 7. 样式策略

- 保持现有渐变、留白、圆角和白底卡片的看板氛围。
- `Admin` 只做细节统一，不改变现有主观视觉方向。
- `AgentWorkspace` 对卡片层级、模块分隔和信息顺序做结构优化。
- 统一按钮、空态、标题、副标题、badge、图表容器的视觉语言。

## 8. 实施步骤

1. 清理 `Admin.vue` 剩余乱码文案与残留模板问题。
2. 修复 `Admin.vue` 趋势图渲染与时间窗联动逻辑。
3. 重新整理 `AgentWorkspace.vue` 的模板结构，恢复可解析和可展示状态。
4. 按新的四层结构重排 `AgentWorkspace.vue` 模块。
5. 统一两页的局部样式细节。
6. 运行前端构建验证，确保页面至少通过编译。

## 9. 验证方式

至少进行以下验证：

- `npm run build`
- 手工检查 `Admin`：
  - 页面中文显示正常
  - 切换 `Top5` 时间窗时，趋势图不消失
  - 切换 `近 3 月 / 近 6 月` 时趋势图能正常渲染
- 手工检查 `AgentWorkspace`：
  - 页面无模板错乱
  - 模块顺序符合新结构
  - 图表与卡片正常展示

## 10. 风险与控制                                                                    

风险：

- `AgentWorkspace.vue` 目前源码损坏较重，局部改动可能持续触发新的语法问题。
- 两页都使用 ECharts，如果修复方式不一致，后续又会出现一边正常一边异常。

控制方式：

- 对 `Admin` 采取最小改动策略。
- 对 `AgentWorkspace` 先恢复结构，再做模块重排，不在损坏模板上继续打补丁。
- 每完成一个阶段就跑一次构建，避免最后集中爆错。
